## Summary
[summary]: #summary

Rendering the frames of the main character sprite sheet to the screen subject to user input.

A sprite sheet is an ordinary image divided into a grid of frames, each with the same dimensions (e.g., 32x32). 
Each row of the grid is an animation: playing it means showing the row’s frames one after another, then looping back to the first frame.
```
        +----0----+----1----+----2----+----3----+
        |    o    |    o/   |    o    |   \o/   |
row 0   |   /|\   |   /|    |   /|\   |    |    |
        |   / \   |   / \   |   / \   |   / \   |
        +----4----+----5----+----6----+----7----+
        |    o/   |   \o/   |   \o    |         |
row 1   |   /|    |    |    |    |\   |  empty  |
        |   / \   |   / \   |   / \   |         |
        +---------+---------+---------+---------+
```

The way to think about it: an animation is just an index that cycles over time. 
The grid is numbered left to right, top to bottom, so every frame has a single index, and playing an animation means stepping that index through the frames of a row.
For example, suppose the animation of `row 0` should play while the player holds `W`:

1. We attach an animation component to the player entity. It keeps track of the state needed to render the animation: the current `index`, a `timer`, and which `animation`.
If we each animation is a variant of a sum type we can pattern match on a animation and get its metadata, such as where its frames start and how many there are (4 for `row 0`).
2. A system reads the keyboard input each frame. While W is held, it selects the `row 0` animation, and sets `index` to the animation’s first frame.
3. A second system ticks the timer. Each time the timer fires, it increments `index`, wrapping back to the animation’s first frame after the last, and updates the sprite to show the frame at `index`.
